## 范围

1. **F1（P1）回忆轮 2 重评重复计「新学/复习」**：
   - 现象：`RecallSession.advance()` 轮 2 重排队时 `rating = null`，VM 以 `item.rating == null` 判「首评」→ `logDelta` 再次计入新学/复习；实际记录已在轮 1 创建（本次是 update）
   - 违反 PRD 修订 #21「新学 = 首次评级**创建记录**的词数」；与考察侧同条款口径（ledgered，重考只计判定+复习）不一致
   - 修法（对齐 ISSUE-009 ledgered 语义）：`RecallItem` 增 `everRated` 标记，轮 2 重排队置位；`logDelta` 三分支——首评（rating==null 且未 everRated）= 新学/复习按 hadRecord；重评（rating==null 且 everRated）= 复习+1；批内改评（rating!=null）= 仅判定（ISSUE-006 既定口径不变）
   - TDD：RecallSessionTest 增「轮 2 重评计复习不计新学」「改评仍只计判定」用例，先红后绿
2. **F2（P2，2026-09-16 用户改口径，PRD 修订 #28）**：悬停只做视觉预览高亮、不改变选中态；选中态仅由鼠标点击或键盘上下键更新；选中项（深底色+左指示条）与悬停项（浅底色）样式可区分
   - 通览 HomeScreen：悬停当前与选中同底色 → 拆分为两档样式
   - 回忆 RecallScreen：移除 `LaunchedEffect(hovered) { onSelect() }`（悬停=选中）；同样拆分两档样式
   - 交互影响留档：回忆屏 Q 偷看与 1-4 快捷键作用于「选中项」，悬停不再改变选中
   - **修复追加（2026-09-16 20:49，f4b324e）**：19d4436 拆分样式后用户实机仍报「悬停深、选中浅」——根因为两屏行组件 `clickable` 裸调用自带默认 ripple，悬停 state layer（onSurface≈8%）叠自绘悬停底色 2.5% ≈ 10.5%，反压选中态自绘 4.5%。修法：clickable 复用悬停 interactionSource + indication=null（设计稿无 ripple，点击反馈由深底+指示条+播报承接），悬停视觉全交自绘三态；分组头/按钮类未动。待用户实机复验
