# 词条唯一键 =（英文文本, 词性）联合唯一

设计稿导入弹窗与 PRD §2.1.1 存在口径冲突：前者按「英文（忽略大小写）+ 词性完全一致」判重，后者按 text 单列唯一。本质分歧是「一条词条是什么」。决策：**唯一键 = (text, pos) 联合**，两列均 COLLATE NOCASE；pos 归一化后存储（trim、小写、去尾部点号，如 `n`），空词性 = 空串（NOT NULL 禁 NULL——SQLite UNIQUE 中 NULL 互不相等，否则 `(apple, NULL)` 可无限插入）。语义收益：多义词条目共存（record/n.「记录」与 record/v.「录制」是两个学习对象），义项分开记账、分开排期；导入不再静默丢弃第二词性。被否掉的备选：**text 单列唯一**（原口径——多义词条目被静默跳过，丢数据且与设计稿矛盾）；**Word/Sense 义项子表**（词典学正解，但考核面挂接语义全变、三表联动，MVP 悬崖，留作后续演进）。已知代价：①听→拼面冗余——同文本双词性的两条目听写刺激（音频）与反应（拼写）完全相同，同日可能考两遍同样拼写（低频，可忍；将来可在工作集按 text 去重展示）；②两义项中文释义相同时中→英判定无法区分（极低频）；③导入/添加的判重、编辑改词性的撞键校验都要走归一化函数，实现需单点收敛（勿散落手写）。与 ADR 0004 正交：考核面仍按词条粒度分账。
